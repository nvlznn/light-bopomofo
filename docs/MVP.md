# 輕注音 MVP

**目標**：在 macOS 上用簡拼 + 整段轉換打出一則 Slack／LINE 訊息；打錯時可以只選前段，剩下的繼續選。
判準：Ino 願意把它設成預設輸入法，只有打不出來時才切回系統注音。

## 範圍

**引擎（Rust）**
- 大千鍵位 → 注音
- 字首與完整注音混打（每個槽位只要是該字讀音的開頭）
- 聲調 3/4/6/7 結束一個字，並過濾聲調不符的候選
- 詞格 + Viterbi，只用詞頻（先不做 bigram）
- 候選：整段轉換 → 只涵蓋前段的詞（涵蓋越多越前面）→ 單字
- 選前段：送出該段，剩下的注音留在輸入區重新轉換
- 使用者紀錄：記「輸入的注音 → 選的詞」，下次同樣輸入時排到前面

**macOS 外殼（Swift）**
- 自畫的橫向候選視窗（原本打算用 `IMKCandidates`，但它預設用 1–9 選字並自己攔截按鍵，和大千的數字鍵衝突）
- Space／Enter 送出、←→ 移動、Backspace、Esc、Caps Lock 時交還系統
- 標點：Shift + `,` `.` `/` `1` `;` → ，。？！：
- 輸入區有內容時按到其他鍵：先送出選中的候選，再交還系統
- `make`／腳本安裝到 `~/Library/Input Methods`，ad-hoc 簽署

**詞庫**：libchewing-data 的 `tsi.csv`（LGPL-2.1-or-later），用 `scripts/fetch-lexicon.sh` 下載，不放進 git。

## 與完整計畫的差異（暫時）
1. C ABI 只有少數函式；引擎是無狀態查詢，輸入區與按鍵處理先放在 Swift。
2. 不用 Xcode 專案，用 `swiftc` + 腳本組 `.app`。
3. 只編 arm64。

## 已知限制
- 只用詞頻：長句的整段轉換常常不準（例如 ㄊㄑㄏㄏ → 碳氫化合）。
- chewing 的單字頻率是分層壓平的（的/得/地 = 147270/147269/147269）。已處理：同一層內（相差 1% 內）改依「含該字的詞頻總和」排序。不同層之間仍沿用 chewing 的判斷，例如 ㄕˋ 的「試」仍排在「事」前面。
